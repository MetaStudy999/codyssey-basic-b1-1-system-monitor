# 02. 저장소와 작업 기록 체계

## 목표

브랜치, 커밋, Pull Request, 보고서, 증빙 파일의 역할과 규칙을 확정합니다.

## 핵심 원칙

- 원본 미션·평가 문서는 수정하지 않음
- `main` 직접 수정 대신 작업 브랜치 사용
- 실제 비밀값과 시스템 백업은 Git에서 제외
- 진행 상태는 `docs/README.md`에서 관리

## 완료 조건

- [ ] 작업 브랜치 확인
- [ ] `.gitignore` 확인
- [ ] 증빙 파일 이름 규칙 확인
- [ ] 보고서와 증빙 역할 구분
