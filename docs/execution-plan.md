# B1-1 미션 실행 계획

## 0. 운영 원칙

이 계획은 B1-1을 빠르게 완료하면서도 평가 누락을 방지하기 위해 다음 순서로 진행합니다.

```text
요구사항 확인 → 구현 → 검증 → 증빙 → 설명 준비
```

각 단계는 통과 조건을 충족한 뒤 다음 단계로 이동합니다.

---

## 1. 미션 통제표

### 1.1 목표

보안이 적용된 Linux 실행 환경을 구성하고, 제공 Agent 애플리케이션의 프로세스·포트·자원 상태를 Bash 스크립트로 자동 점검하여 로그로 남깁니다.

### 1.2 최종 결과물

- 요구사항 수행 내역서
- `monitor.sh`
- 필수 설정 및 실행 증빙
- 정상·장애 테스트 결과

### 1.3 관리 문서

- `docs/requirements.md`: 요구사항-구현-증빙 추적표
- `docs/execution-record.md`: 실제 명령과 결과 기록
- `docs/troubleshooting.md`: 오류 분석과 해결 기록
- `docs/final-checklist.md`: 제출 전 최종 검수
- `evidence/README.md`: 증빙 저장 규칙

## 2. 실습 환경과 안전 계획

### 작업

1. Ubuntu 버전과 CPU 아키텍처를 확인합니다.
2. `systemd`, `sshd`, cron, UFW 또는 firewalld 사용 가능 여부를 확인합니다.
3. sudo 권한과 로컬 콘솔 또는 복구 접속 경로를 확보합니다.
4. SSH 설정 파일을 변경하기 전에 백업합니다.
5. 시스템 초기 상태를 증빙으로 저장합니다.

### SSH 안전 변경 순서

```text
설정 백업
→ 20022 방화벽 선허용
→ sshd 설정 수정
→ sshd -t 문법 검사
→ SSH 서비스 재시작
→ 새 터미널에서 20022 접속 확인
→ 기존 세션 종료
```

### 통과 조건 G1

- [ ] sudo 사용 가능
- [ ] `systemd`, `sshd`, cron, 방화벽 도구 확인
- [ ] SSH 설정 백업 완료
- [ ] 접속 실패 시 복구 경로 확보

## 4. SSH와 방화벽 보안

### 작업

1. SSH 접속 포트를 `20022`로 변경합니다.
2. Root 원격 로그인을 차단합니다.
3. `sshd -t`로 문법을 검사합니다.
4. `20022` 리슨과 실제 접속을 검증합니다.
5. UFW 또는 firewalld를 활성화합니다.
6. 인바운드 `20022/tcp`, `15034/tcp`를 허용합니다.
7. 불필요한 인바운드 규칙을 제거합니다.
8. 허용·차단 결과를 증빙합니다.

### 통과 조건 G3

- [ ] SSH `20022` LISTEN
- [ ] Root 원격 로그인 차단
- [ ] 방화벽 활성화
- [ ] `20022/tcp`, `15034/tcp` 허용
- [ ] 새 포트로 접속 성공

## 5. 사용자·그룹·권한·ACL

### 작업

1. `agent-admin`, `agent-dev`, `agent-test`를 생성합니다.
2. `agent-common`, `agent-core`를 생성합니다.
3. 다음 구성원을 등록합니다.
   - `agent-common`: admin, dev, test
   - `agent-core`: admin, dev
4. `$AGENT_HOME`, `upload_files`, `api_keys`, `/var/log/agent-app`, `bin`을 생성합니다.
5. `upload_files`는 `agent-common`이 읽기·쓰기가 가능하도록 구성합니다.
6. `api_keys`와 로그 디렉터리는 `agent-core`로 제한합니다.
7. `agent-test`의 허용·차단 동작을 실제 계정으로 시험합니다.

### 통과 조건 G4

- [ ] 사용자 3개와 그룹 2개 생성
- [ ] 그룹 구성원 요구사항 충족
- [ ] 공유 디렉터리 접근 성공
- [ ] `agent-test`의 보안 디렉터리 접근 차단
- [ ] 소유권·권한·ACL 증빙 완료

## 6. Agent 애플리케이션 배치와 실행

### 작업

1. `agent-app.zip`을 분석하고 CPU 아키텍처에 맞는 실행 파일을 선택합니다.
2. 실행 권한을 설정합니다.
3. 다음 환경변수를 설정합니다.
   - `AGENT_HOME`
   - `AGENT_PORT=15034`
   - `AGENT_UPLOAD_DIR=$AGENT_HOME/upload_files`
   - `AGENT_KEY_PATH=$AGENT_HOME/api_keys/t_secret.key`
   - `AGENT_LOG_DIR=/var/log/agent-app`
4. 키 파일을 생성하고 최소 권한을 적용합니다.
5. 일반 사용자로 Agent를 실행합니다.
6. Boot Sequence 5단계 `[OK]`, `Agent READY`를 확인합니다.
7. `0.0.0.0:15034` LISTEN을 확인합니다.

### 통과 조건 G5

- [ ] 일반 사용자 실행
- [ ] Boot Sequence 5단계 통과
- [ ] `Agent READY` 출력
- [ ] TCP `15034` LISTEN
- [ ] 로그 디렉터리 쓰기 가능

## 7. `monitor.sh` 설계와 구현

### 책임

```text
환경 검증
→ 프로세스 Health Check
→ 포트 Health Check
→ 방화벽 상태 점검
→ CPU/MEM/DISK 수집
→ 임계값 경고
→ 로그 누적
```

### 권장 함수 구조

```text
main
├── validate_environment
├── check_process
├── check_port
├── check_firewall
├── collect_cpu
├── collect_memory
├── collect_disk
├── print_warnings
└── append_log
```

### 구현 기준

- Bash로 작성
- 절대경로 사용
- 변수 인용과 명령 실패 처리
- cron의 제한된 환경에서도 동작
- 프로세스·포트 비정상 시 `exit 1`
- 방화벽 비활성 및 임계값 초과는 경고 후 계속 실행
- 지정 로그 포맷 사용
- `bash -n` 및 가능하면 ShellCheck 실행

### 통과 조건 G6

- [ ] 정상 상태 `exit 0`
- [ ] 프로세스 실패 `exit 1`
- [ ] 포트 실패 `exit 1`
- [ ] CPU, MEM, DISK 값 출력
- [ ] 임계값 경고 출력
- [ ] 지정 포맷으로 로그 기록

## 8. 로그 관리와 cron 자동화

### 작업

1. `/var/log/agent-app/monitor.log`의 소유권과 쓰기 권한을 확인합니다.
2. 로그가 반복 실행 시 누적되는지 확인합니다.
3. logrotate 또는 스크립트 방식으로 `10MB / 10개` 정책을 적용합니다.
4. 강제 회전으로 설정을 검증합니다.
5. `agent-admin`의 crontab에 매분 실행을 등록합니다.
6. cron에서 필요한 절대경로와 환경변수를 명시합니다.
7. 실행 전후 로그 줄 수와 타임스탬프를 비교합니다.

### 통과 조건 G7

- [ ] `monitor.log` 누적
- [ ] 로그 관리 `10MB / 10개`
- [ ] `agent-admin` cron 매분 등록
- [ ] 1~2분 후 로그 자동 증가
- [ ] cron 실패 시 진단 방법 기록

## 9. 정상·장애 테스트

| 시나리오 | 조작 | 예상 결과 |
|---|---|---|
| 정상 상태 | Agent와 포트 정상 | 자원 수집, 로그 기록, `exit 0` |
| 프로세스 없음 | Agent 종료 | 오류 출력, `exit 1` |
| 포트 미리슨 | 프로세스는 존재하나 `15034` 미리슨 | 오류 출력, `exit 1` |
| 방화벽 비활성 | 방화벽 비활성화 | `[WARNING]`, 계속 실행 |
| CPU 초과 | 재현 또는 테스트 방식 사용 | `[WARNING]`, 계속 실행 |
| MEM 초과 | 재현 또는 테스트 방식 사용 | `[WARNING]`, 계속 실행 |
| DISK 초과 | 재현 또는 테스트 방식 사용 | `[WARNING]`, 계속 실행 |
| 로그 권한 오류 | 쓰기 권한 제거 | 명확한 오류와 비정상 종료 |
| cron 환경 오류 | 변수·경로 누락 재현 | 원인 식별 및 수정 기록 |
| 로그 회전 | 강제 회전 | 회전 파일과 유지 정책 확인 |

### 테스트 기록 형식

```markdown
## 테스트 이름
- 목적:
- 사전 조건:
- 실행 명령:
- 예상 결과:
- 실제 결과:
- 종료 코드:
- 증빙 파일:
- 판정: PASS / FAIL
```
