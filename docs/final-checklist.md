# B1-1 최종 검수 체크리스트

제출 직전에 실제 환경에서 위에서 아래 순서로 검수합니다. 문서 존재 여부만 확인하지 않고, 명령과 동작 결과를 다시 확인합니다.

## 1. 환경과 복구

- [ ] Ubuntu 버전과 CPU 아키텍처를 기록했다.
- [ ] `systemd`, SSH, cron, 방화벽 도구가 동작한다.
- [ ] SSH 설정 원본 백업이 존재한다.
- [ ] SSH 변경 실패 시 로컬 콘솔 또는 기존 세션으로 복구할 수 있다.

## 2. SSH와 방화벽

- [ ] `sudo sshd -t`가 오류 없이 종료된다.
- [ ] SSH가 TCP `20022`에서 LISTEN한다.
- [ ] 새 터미널에서 `20022`로 접속된다.
- [ ] Root 원격 로그인이 차단되어 있다.
- [ ] UFW 또는 firewalld가 활성 상태다.
- [ ] 인바운드 `20022/tcp`, `15034/tcp`가 허용되어 있다.
- [ ] 불필요한 전체 포트 허용 규칙이 없다.
- [ ] 관련 명령 출력이 `evidence/`에 저장되어 있다.

## 3. 계정·그룹·권한

- [ ] `agent-admin`, `agent-dev`, `agent-test`가 존재한다.
- [ ] `agent-common`, `agent-core`가 존재한다.
- [ ] `agent-common`에 admin/dev/test가 포함되어 있다.
- [ ] `agent-core`에 admin/dev가 포함되어 있다.
- [ ] `upload_files`에서 `agent-common` 사용자가 필요한 읽기·쓰기를 수행할 수 있다.
- [ ] `api_keys`와 `/var/log/agent-app`는 `agent-core`로 제한된다.
- [ ] `agent-test`의 보안 디렉터리 접근 실패가 검증되었다.
- [ ] `ls -l`, `id`, `getfacl` 결과를 증빙했다.

## 4. Agent 실행 환경

- [ ] `AGENT_HOME`이 올바르다.
- [ ] `AGENT_PORT=15034`이다.
- [ ] `AGENT_UPLOAD_DIR=$AGENT_HOME/upload_files`이다.
- [ ] `AGENT_KEY_PATH=$AGENT_HOME/api_keys/t_secret.key`이다.
- [ ] `AGENT_LOG_DIR=/var/log/agent-app`이다.
- [ ] 키 파일이 존재하며 권한이 과도하게 열려 있지 않다.
- [ ] Agent가 Root가 아닌 일반 사용자로 실행된다.
- [ ] Boot Sequence 5단계가 모두 `[OK]`다.
- [ ] 마지막에 `Agent READY`가 출력된다.
- [ ] `0.0.0.0:15034` LISTEN이 확인된다.

## 5. `monitor.sh`

- [ ] 파일 경로가 `$AGENT_HOME/bin/monitor.sh`이다.
- [ ] 소유자가 `agent-dev`이다.
- [ ] 그룹이 `agent-core`이다.
- [ ] 권한이 `750`이다.
- [ ] `bash -n` 문법 검사를 통과한다.
- [ ] 가능하면 ShellCheck 주요 오류를 해결했다.
- [ ] 프로세스가 정상일 때 PID를 확인한다.
- [ ] 포트 `15034`가 정상일 때 `[OK]`를 출력한다.
- [ ] 프로세스가 없으면 `exit 1`이다.
- [ ] 포트가 열리지 않으면 `exit 1`이다.
- [ ] 방화벽 비활성은 `[WARNING]` 후 계속 실행한다.
- [ ] CPU 사용률을 수집한다.
- [ ] 메모리 사용률을 수집한다.
- [ ] 루트 파티션 디스크 사용률을 수집한다.
- [ ] CPU `>20%` 경고가 구현되어 있다.
- [ ] MEM `>10%` 경고가 구현되어 있다.
- [ ] DISK `>80%` 경고가 구현되어 있다.
- [ ] 값 추출 실패 시 빈 값이나 잘못된 로그를 남기지 않는다.

## 6. 로그와 자동 실행

- [ ] `/var/log/agent-app/monitor.log`에 기록된다.
- [ ] 로그가 다음 형식과 동등한 한 줄 구조다.

```text
[YYYY-MM-DD HH:MM:SS] PID:... CPU:..% MEM:..% DISK_USED:..%
```

- [ ] 반복 실행 시 기존 로그를 덮어쓰지 않고 누적한다.
- [ ] 로그 파일의 소유권과 권한이 적절하다.
- [ ] `10MB / 10개` 로그 관리 정책이 설정되어 있다.
- [ ] 강제 로그 회전 결과를 확인했다.
- [ ] `agent-admin`의 crontab에 매분 실행이 등록되어 있다.
- [ ] cron 명령에 절대경로를 사용한다.
- [ ] cron 환경에서 필요한 환경변수를 제공한다.
- [ ] 1~2분 전후로 `monitor.log`가 자동 증가한다.

## 7. 장애 테스트

- [ ] 정상 상태에서 `exit 0`과 로그 기록을 확인했다.
- [ ] Agent 종료 후 프로세스 실패와 `exit 1`을 확인했다.
- [ ] 프로세스는 있으나 포트 미리슨 상황을 시험했다.
- [ ] 방화벽 비활성 경고를 확인했다.
- [ ] 자원 임계값 경고를 확인했다.
- [ ] 로그 쓰기 권한 실패를 시험했다.
- [ ] cron에서만 발생하는 경로·환경변수 문제를 점검했다.
- [ ] 로그 회전 실패 시 확인할 명령을 기록했다.
- [ ] 각 테스트에 예상 결과, 실제 결과, 종료 코드, 증빙 파일이 있다.

## 8. 설명 준비

- [ ] SSH 포트 변경과 Root 로그인 차단의 보안 효과를 설명할 수 있다.
- [ ] 방화벽에서 필요한 포트만 허용하는 이유를 설명할 수 있다.
- [ ] `agent-common`과 `agent-core`를 나눈 이유를 최소 권한 원칙으로 설명할 수 있다.
- [ ] 소유자 `agent-dev`, 실행자 `agent-admin`, 그룹 `agent-core`, 권한 `750`의 관계를 설명할 수 있다.
- [ ] 프로세스 검사 명령과 포트 검사 명령을 선택한 이유를 설명할 수 있다.
- [ ] CPU/MEM/DISK 추출과 파싱 방식을 설명할 수 있다.
- [ ] `>`와 `>>`의 차이와 로그 누적에 `>>`가 필요한 이유를 설명할 수 있다.
- [ ] 경고 항목과 즉시 실패 항목을 분리한 운영상 이유를 설명할 수 있다.
- [ ] 프로세스는 실행 중이나 포트가 열리지 않을 때 확인 순서를 설명할 수 있다.
- [ ] 로그 급증 시 단기 대응과 중기 대응을 설명할 수 있다.

## 9. 문서와 증빙

- [ ] README에 프로젝트 소개와 실행 흐름이 있다.
- [ ] `docs/requirements.md`의 모든 필수 상태가 완료되어 있다.
- [ ] `docs/execution-record.md`에 실제 명령과 결과가 기록되어 있다.
- [ ] `docs/troubleshooting.md`에 문제 해결 기록이 있다.
- [ ] 증빙 파일 이름과 문서 링크가 일치한다.
- [ ] 스크린샷만이 아니라 가능한 명령 결과 텍스트도 보관했다.
- [ ] 개인 IP, 비밀번호, API 키 등 민감정보를 마스킹했다.
- [ ] 깨진 링크가 없다.

- [ ] 커밋 메시지가 변경 내용을 식별할 수 있다.
- [ ] 임시 파일, 로그, 키 파일이 커밋되지 않았다.
- [ ] `git status`가 깨끗하다.
- [ ] 최종 브랜치 또는 PR에서 모든 문서를 열 수 있다.
- [ ] 제출용 저장소 URL이 정확하다.
